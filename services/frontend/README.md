# Alpa frontend

A dark React application based on the Alpa platform frames in the [Figma UI kit](https://www.figma.com/design/Os1G7QKEwCmfC3MFtlSqMr?node-id=5034-2). It uses TypeScript, Vite, shadcn/ui Nova, Tailwind, React Router, TanStack Query, React Hook Form, Zod, React Flow and ELK. Fonts and design assets are served locally.

## Development

Requires Node.js 22.13+ and npm.

```sh
npm ci
npm run dev
```

The development server proxies `/v1` to `http://localhost:8080`. Set `ALPA_API_URL` to point it at another local API. The production app uses the same origin. `npm run build` writes `dist`, consumed by the Go server's normal asset loader or the root `make build` embed step. Nested routes require the server's SPA fallback, already provided by the Go service.

## Layout

- `src/app`: routing, workspace selection, sidebar and breadcrumbs.
- `src/api`: generated OpenAPI types, requests, pagination and query invalidation.
- `src/domain`: validation, request adapters, backend technology defaults and visual labels.
- `src/components/ui`: shadcn/ui Nova primitives.
- `src/components/shared`: loading, errors, forms and development screens.
- `src/features`: workspace, products, components and architecture.

The API contract is `../api-server/docs/openapi.yaml`. Run `npm run generate:api` after changing it, then `npm run check:api` to detect drift. Technology defaults match `../api-server/internal/domain/inventory/default_technologies.go`.

## Behavior

Workspace selection persists locally. Product and component URLs include workspace and entity IDs. Legacy `/products/:code` links resolve through the selected workspace, including old `threat-model` and `security` paths. Unknown entities show a not-found screen.

Dashboard, Templates, Teams, Settings, Threat modeling and Security checks intentionally show **In development**. They retain their navigation context and do not invent unavailable API operations.

Each infrastructure API has its own Exposure selection, defaulting to Internal. Infrastructure importancy requires an explicit choice. Component API/client drafts are saved with the component. Editing preserves non-visible fields. Communication is derived for drafts and read from the server for saved clients. Repository URL and client Description are deliberately unavailable in this version, following the approved UI scope.

Architecture opens in another tab. Click a free client and then an API on another component to review a connection, or drag between ports. Escape cancels a pending selection. Search focuses components; selection highlights neighbors; Neighborhood hides unrelated nodes. Position and viewport are saved per product in browser storage. Inventory mutations refresh data in other tabs through BroadcastChannel, with a storage-event fallback.

## Validation

```sh
npm run check:api
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

Playwright uses installed Google Chrome. Tests use isolated API fixtures, including pagination beyond 100 components, failed saves, binding conflicts, hidden-field preservation, independent exposure, two tabs, keyboard access and 1440/1024/390 layouts. Test data is never bundled in the application.

The real API scenario is opt-in and must point to a disposable local server/database. It creates a workspace and attempts deletion during cleanup. The current server lacks that route, so destroy the disposable database afterward:

```sh
ALPA_REAL_API=1 ALPA_E2E_URL=http://127.0.0.1:18080 npm run test:e2e -- tests/e2e/real-api.spec.ts
```

`test-results/visual` contains screenshots generated by browser tests; Playwright's report and traces are ignored by Git.

See [verification results](docs/verification.md) for the completed checks and known limitations.

### Backend compatibility findings

The checked backend snapshot advertises `DELETE /v1/workspaces/{workspace_id}` in OpenAPI but does not register that route in `internal/httpapi/routing.go`. Workspace deletion is implemented against the published contract and tested with fixtures; this server responds with 404. The UI keeps the workspace and shows the error. Enabling that server operation requires a separate backend change.

The isolated backend's existing `golangci-lint` check reports `cmd/main.go:31: exitAfterDefer (gocritic)`. The frontend does not modify backend code.
